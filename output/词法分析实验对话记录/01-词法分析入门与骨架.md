## 一、词法分析到底负责什么

词法分析器主要做四件事：

1. 从左到右读取源码。
2. 跳过空格、换行和注释。
3. 识别关键字、标识符、数字、字符串、运算符等 Token。
4. 记录 Token 所在行号以及词法错误。

它认识的是“单词”，不判断这些单词组成的句子是否合理。

例如：

```c
int = = main;
```

虽然语法明显不对，但词法分析仍然可以切出：

```text
INTTK int
ASSIGN =
ASSIGN =
MAINTK main
SEMICN ;
```

“这样的排列合法吗”由下一阶段判断。

## 二、你这次作业具体要识别什么

根据项目里的[实验1词法分析要求](</home/zzz2007-cpu/projects/compiler/docs/实验要求/实验1词法分析要求.md>)和[完整文法 PDF](</home/zzz2007-cpu/projects/compiler/docs/2026编译技术实验文法定义及相关说明.pdf>)，需要识别以下几类内容。

### 1. 标识符和关键字

标识符规则：

```text
第一个字符：字母或下划线
后续字符：字母、数字或下划线
```

例如：

```text
a
student
_value
test123
```

先读取出完整单词，再查关键字表：

```cpp
int       -> INTTK
char      -> CHARTK
main      -> MAINTK
if        -> IFTK
while     -> WHILETK
```

不在关键字表中的就是：

```text
IDENFR
```

所以：

```c
int integer;
```

结果是：

```text
INTTK int
IDENFR integer
```

不能因为 `integer` 以 `int` 开头，就把它切成 `int` 和 `eger`。

### 2. 整数常量

连续读取数字：

```text
0
12
300
```

对应：

```text
INTCON
```

注意要保留原始字符串。Token 可以同时保存：

```cpp
lexeme = "300";  // 原始文本，用于输出
value = 300;     // 真正数值，后续阶段使用
```

### 3. 字符常量

例如：

```c
'A'
'\n'
'\\'
'\''
```

对应：

```text
CHARCON
```

同样建议既保存原始文本，也保存解码后的数值：

```cpp
lexeme = "'\\n'";
value = 10;
```

### 4. 字符串常量

例如：

```c
"hello"
"value = %d\n"
```

对应：

```text
STRCON
```

作业输出中需要保留双引号：

```text
STRCON "value = %d\n"
```

### 5. 运算符和分隔符

例如：

```text
+  -  *  /  %
=  ==  !=
<  <=  >  >=
!  &&  ||
(  )  [  ]  {  }
,  ;  :
```

这里一定要使用“最长匹配”。

看到 `=` 时：

```text
下一个字符也是 =  -> EQL ==
否则              -> ASSIGN =
```

看到 `<` 时：

```text
下一个字符是 =  -> LEQ <=
否则            -> LSS <
```

### 6. 注释

注释不产生 Token，直接跳过。

```c
// 单行注释
```

跳到换行符。

```c
/* 多行
   注释 */
```

跳到第一次出现的 `*/`，同时注意更新行号。

### 7. 本次词法错误

本次作业要求处理的词法错误只有：

```text
单独出现的 &
单独出现的 |
```

它们的错误码都是：

```text
a
```

例如：

```c
if (a & b)
```

若 `&` 位于第 2 行：

```text
2 a
```

但不能直接把这个字符丢掉。要求是：

- 单独的 `&` 按 `AND` Token 继续处理，但词素保存为 `"&"`。
- 单独的 `|` 按 `OR` Token 继续处理，但词素保存为 `"|"`。
- 同时记录错误 `a`。

这样即使源程序有错误，后面的分析仍然可以继续。

### Lexer.h

词法分析器维护三个核心状态：

```cpp
class Lexer {
private:
    std::string source;
    std::size_t pos = 0;
    int line = 1;

    std::vector<Token> tokens;
    std::vector<CompileError> errors;

public:
    explicit Lexer(const std::string& source);

    void scan();

    const std::vector<Token>& getTokens() const;
    const std::vector<CompileError>& getErrors() const;

private:
    bool isAtEnd() const;
    char peek() const;
    char peekNext() const;
    char advance();
    bool match(char expected);

    void scanOneToken();
    void scanIdentifier();
    void scanNumber();
    void scanCharConstant();
    void scanStringConstant();
    void skipLineComment();
    void skipBlockComment();

    void addToken(TokenType type, const std::string& lexeme, int tokenLine);
    void addError(int errorLine, char code);
};
```

这些辅助函数的含义是：

```text
peek()       看当前字符，但不移动
peekNext()   看下一个字符
advance()    取出当前字符，并向后移动
match('=')   如果当前字符是 '='，就消费它并返回 true
isAtEnd()    是否到达源码结尾
```

## 四、扫描器的核心流程

核心思想就是一个循环：

```cpp
void Lexer::scan() {
    while (!isAtEnd()) {
        scanOneToken();
    }
}
```

`scanOneToken()` 按下面的顺序判断：

```text
读取当前字符
    │
    ├─ 空格、Tab、回车 → 跳过
    ├─ 换行           → line++
    ├─ 字母或下划线   → 标识符/关键字
    ├─ 数字           → 整数常量
    ├─ 单引号         → 字符常量
    ├─ 双引号         → 字符串常量
    ├─ /              → 除号、//注释或/*注释
    ├─ = ! < >        → 检查是否为双字符运算符
    ├─ &              → &&，或记录错误a
    ├─ |              → ||，或记录错误a
    └─ 其他符号       → 单字符Token
```

伪代码大概是：

```cpp
void Lexer::scanOneToken() {
    int tokenLine = line;
    char ch = advance();

    if (ch == ' ' || ch == '\t' || ch == '\r') {
        return;
    }

    if (ch == '\n') {
        line++;
        return;
    }

    if (isLetter(ch) || ch == '_') {
        scanIdentifier();
        return;
    }

    if (isDigit(ch)) {
        scanNumber();
        return;
    }

    switch (ch) {
        case '\'':
            scanCharConstant();
            break;

        case '"':
            scanStringConstant();
            break;

        case '=':
            if (match('=')) {
                // EQL ==
            } else {
                // ASSIGN =
            }
            break;

        case '&':
            if (match('&')) {
                // AND &&
            } else {
                // AND &
                // error: tokenLine, 'a'
            }
            break;

        case '/':
            if (match('/')) {
                skipLineComment();
            } else if (match('*')) {
                skipBlockComment();
            } else {
                // DIV /
            }
            break;

        // 其他字符……
    }
}
```

这不是完整答案代码，而是你整个词法分析器最核心的骨架。

## 五、标识符怎么扫描

假设当前已经读到了第一个字母，接下来一直读取：

```text
字母、数字、下划线
```

伪代码：

```cpp
while (isLetterOrDigit(peek()) || peek() == '_') {
    advance();
}
```

得到完整字符串后查关键字表：

```cpp
std::unordered_map<std::string, TokenType> keywords = {
    {"int", TokenType::INTTK},
    {"char", TokenType::CHARTK},
    {"main", TokenType::MAINTK},
    {"if", TokenType::IFTK},
    {"else", TokenType::ELSETK}
    // 继续补齐……
};
```

判断：

```cpp
auto it = keywords.find(word);

if (it != keywords.end()) {
    addToken(it->second, word, tokenLine);
} else {
    addToken(TokenType::IDENFR, word, tokenLine);
}
```

## 六、字符串和字符常量怎么扫描

### 字符串

读到 `"` 后，一直扫描到下一个 `"`：

```cpp
while (!isAtEnd() && peek() != '"') {
    if (peek() == '\n') {
        line++;
    }
    advance();
}
```

最后消费右边的 `"`。

要注意：输出的 `lexeme` 必须包含左右双引号。

### 字符

读到 `'` 后，需要考虑普通字符和转义字符：

```text
'A'     普通字符
'\n'    转义字符
'\\'    反斜杠
'\''    单引号
```

可以按照这个思路：

```text
消费左单引号
如果下一个字符是反斜杠：
    消费反斜杠和转义字符
否则：
    消费一个普通字符
消费右单引号
```

第一版先保证能正确保留原始文本。解码字符真实数值可以作为第二步完成。

`main.cpp` 不应该自己识别 Token。它只负责：

## 九、最容易踩的坑

- 把 `integer` 错误地识别成关键字 `int` 加标识符 `eger`。
- 先识别 `=`，导致 `==` 被切成两个赋值号。
- 看到 `/` 就直接认为是除号，没有检查注释。
- 跳过多行注释时没有更新行号。
- 字符串输出时丢掉双引号。
- 把字符串中的 `\n` 直接变成真实换行，导致输出被拆成两行。
- 只保存数值，没有保存原始文本。
- 遇到错误后立即停止，没有继续扫描剩余代码。
- 某个未知字符既不消费也不返回，造成死循环。
- 使用 `while (!file.eof())` 读取文件，容易多读一次；更适合一次性读取整个文件。

你现在真正应该做的第一件事，是先写出 `Token`、`Lexer` 两个结构，并完成 `peek/advance/match`。等这三个函数正确后，后面的工作本质上就是不断增加字符分类规则。

你的理解基本正确，但需要补充一句：

> 词法分析不是判断“这段代码写得对不对”，而是判断“当前这些字符能组成什么单词 Token”。

比如：

```c
int age = 18;
```

词法分析器会从左到右切成：

```text
INTTK int
IDENFR age
ASSIGN =
INTCON 18
SEMICN ;
```

## 词法分析器的工作方式

可以把它想象成一个带指针的扫描器：

```text
int age = 18;
^
当前位置 pos
```

识别完 `int` 后，指针向后移动：

```text
int age = 18;
    ^
```

然后继续识别 `age`，直到文件末尾。

核心状态只有这几个：

```cpp
std::string source;  // 整个源文件
int pos = 0;         // 当前扫描位置
int line = 1;        // 当前行号
```

核心循环：

```cpp
while (pos < source.size()) {
    // 根据 source[pos] 判断接下来是什么
}
```

## 每次看到一个字符应该怎么办

按照下面的顺序判断：

```text
当前字符
    │
    ├─ 空格或 Tab      → 跳过
    ├─ 换行            → line++，然后跳过
    ├─ 字母或下划线    → 读取完整标识符或关键字
    ├─ 数字            → 读取完整整数
    ├─ 单引号 '        → 读取字符常量
    ├─ 双引号 "        → 读取字符串常量
    ├─ /               → 判断是除号还是注释
    ├─ = ! < >         → 判断单字符或双字符运算符
    ├─ & 或 |          → 判断是否合法
    └─ 其他符号        → 查单字符符号表
```

例如当前字符是字母：

```c
student123
^
```

就一直读取，直到遇到“不属于字母、数字、下划线”的字符：

```cpp
while (isalnum(source[pos]) || source[pos] == '_') {
    pos++;
}
```

于是得到：

```text
student123
```

然后查询关键字表：

```cpp
if (word == "int") {
    // INTTK
} else if (word == "if") {
    // IFTK
} else {
    // IDENFR
}
```

实际编写时建议用 `unordered_map` 保存关键字，不需要写很多 `else if`。

## “能识别”和“代码正确”不是一回事

比如：

```c
int = + ;
```

这段代码语法明显错误，但每个词都可以识别：

```text
INTTK int
ASSIGN =
PLUS +
SEMICN ;
```

因此，词法分析阶段不会报错。

这些错误要留给后面的阶段：

- `int = + ;`：语法错误。
- 使用未定义变量：语义错误。
- 单独出现 `&` 或 `|`：本次作业规定的词法错误。

## 这次作业遇到不能识别的字符怎么办

根据本次实验要求，词法阶段明确要求处理的错误只有：

```text
单独出现的 &
单独出现的 |
```

正确写法应该是：

```c
a && b
a || b
```

错误写法：

```c
a & b
a | b
```

遇到单独的 `&`：

1. 记录当前行的错误 `a`。
2. 仍然生成 `AND` Token。
3. Token 原始内容保存为 `"&"`。
4. 继续扫描后面的代码，不能停止。

例如：

```c
if (1 & 2)
```

如果在第 3 行：

```text
error.txt：

3 a
```

但是词法分析器内部仍会形成：

```text
IFTK if
LPARENT (
INTCON 1
AND &
INTCON 2
RPARENT )
```

单独的 `|` 同理，按 `OR` Token 继续处理。

代码逻辑类似：

```cpp
if (current == '&') {
    if (peekNext() == '&') {
        // 识别 &&
        addToken(TokenType::AND, "&&", line);
        pos += 2;
    } else {
        // 单独的 & 是词法错误
        addError(line, 'a');
        addToken(TokenType::AND, "&", line);
        pos++;
    }
}
```

这里最重要的是：

> 报错不等于停止。记录错误以后，还要继续完成整个文件的词法分析。

## 不在要求中的奇怪字符怎么办

例如：

```c
int a = @;
```

`@` 不属于这个语言。

虽然老师的测试一般不会出现规定之外的词法错误，但为了防止程序卡死，你至少要消费掉这个字符：

```cpp
pos++;
```

否则扫描器一直停留在 `@`，会进入死循环。

你可以暂时这样处理：

```cpp
default:
    pos++;  // 暂时跳过未知字符
    break;
```

但不要擅自把它记录为错误 `a`，因为 `a` 只表示单独的 `&` 或 `|`。

## 你现在应该先写哪一部分

先不要急着把所有 Token 一次写完。第一步写下面这些基础函数：

```cpp
bool Lexer::isAtEnd() const {
    return pos >= source.size();
}

char Lexer::peek() const {
    if (isAtEnd()) {
        return '\0';
    }
    return source[pos];
}

char Lexer::peekNext() const {
    if (pos + 1 >= source.size()) {
        return '\0';
    }
    return source[pos + 1];
}

char Lexer::advance() {
    return source[pos++];
}

bool Lexer::match(char expected) {
    if (isAtEnd() || source[pos] != expected) {
        return false;
    }

    pos++;
    return true;
}
```

然后写扫描主循环：

```cpp
void Lexer::scan() {
    while (!isAtEnd()) {
        scanOneToken();
    }
}
```

第一版 `scanOneToken()` 只实现三种东西：

1. 空白和换行。
2. 标识符和关键字。
3. 整数。

用下面的输入测试：

```c
int main
abc
123
```

期望得到：

```text
INTTK int
MAINTK main
IDENFR abc
INTCON 123
```

这一步成功以后，再逐个添加运算符、注释、字符和字符串。这样调试起来最轻松。

```cpp
Lexer::Lexer(const std::string& code)

}

void Lexer::scan() {
    while (pos < source.size()) {
        char current = source[pos];

        std::cout << current;

        if (current == '\n') {
            line++;
        }

        pos++;
    }
}
```

```cpp
Lexer lexer(source);
```

## 第一步：定义 Token 类别

在 `Token.h` 中定义所有单词类别：

```cpp
#ifndef TOKEN_H
#define TOKEN_H

#include <string>

enum class TokenType {
    // 标识符和常量
    IDENFR,
    INTCON,
    CHARCON,
    STRCON,

    // 关键字
    MAINTK,
    CONSTTK,
    INTTK,
    CHARTK,
    VOIDTK,
    IFTK,
    ELSETK,
    WHILETK,
    BREAKTK,
    CONTINUETK,
    RETURNTK,
    PRINTFTK,
    STATICTK,
    SWITCHTK,
    CASETK,
    DEFAULTTK,

    // 运算符
    NOT,
    AND,
    OR,
    PLUS,
    MINU,
    MULT,
    DIV,
    MOD,
    LSS,
    LEQ,
    GRE,
    GEQ,
    EQL,
    NEQ,
    ASSIGN,

    // 分隔符
    SEMICN,
    COMMA,
    COLON,
    LPARENT,
    RPARENT,
    LBRACK,
    RBRACK,
    LBRACE,
    RBRACE
};

struct Token {
    TokenType type;       // 单词类别
    std::string lexeme;   // 源代码中的原始内容

};

#endif
```


关键字是固定字符串，适合使用 `unordered_map`。

```cpp
#include "Lexer.h"

static const std::unordered_map<std::string, TokenType> keywords = {
    {"main",     TokenType::MAINTK},
    {"const",    TokenType::CONSTTK},
    {"int",      TokenType::INTTK},
    {"char",     TokenType::CHARTK},
    {"void",     TokenType::VOIDTK},
    {"if",       TokenType::IFTK},
    {"else",     TokenType::ELSETK},
    {"while",    TokenType::WHILETK},
    {"break",    TokenType::BREAKTK},
    {"continue", TokenType::CONTINUETK},
    {"return",   TokenType::RETURNTK},
    {"printf",   TokenType::PRINTFTK},
    {"static",   TokenType::STATICTK},
    {"switch",   TokenType::SWITCHTK},
    {"case",     TokenType::CASETK},
    {"default",  TokenType::DEFAULTTK}
};
```

扫描到一串字母后，查表：

```cpp
auto it = keywords.find(word);

if (it != keywords.end()) {
    // 找到了，是关键字
    addToken(it->second, word, line);

    // 没找到，是普通标识符
    addToken(TokenType::IDENFR, word, line);
}
```

因此：


```cpp
    break;
```

```cpp
std::string tokenTypeToString(TokenType type) {
    switch (type) {
        case TokenType::IDENFR: return "IDENFR";
        case TokenType::INTCON: return "INTCON";
        case TokenType::CHARCON: return "CHARCON";
        case TokenType::STRCON: return "STRCON";

        case TokenType::MAINTK: return "MAINTK";
        case TokenType::CONSTTK: return "CONSTTK";
        case TokenType::INTTK: return "INTTK";
        case TokenType::CHARTK: return "CHARTK";
        case TokenType::VOIDTK: return "VOIDTK";

        // 后面继续补齐

        default: return "UNKNOWN";
    }
}
```

输出 Token 时：

```cpp
outputFile
    << tokenTypeToString(token.type)
    << " "
    << token.lexeme
    << "\n";
```

| 内容 | 识别方法 |
|---|---|
| `int`、`if`、`while` | 读取完整单词后查关键字表 |
| `+`、`;`、`(` | 查单字符符号表 |
| `==`、`!=`、`&&` | 查看当前字符和下一个字符 |
| `student123` | 按标识符规则连续读取 |
| `12345` | 按数字规则连续读取 |
| `"hello"` | 一直读到右双引号 |
| 注释 | 一直跳过到换行或 `*/` |

所以你要定义的是：

```text
Token 类别 enum
关键字映射表
单字符符号映射表
双字符运算符判断规则
```

而不是给每一个可能出现的变量名和数字准备模板。变量名、数字、字符和字符串都是通过规则识别的。

这些名字分为两类：

## 一、TokenType 中的名字来自实验要求

例如：

```cpp
enum class TokenType {
    IDENFR,
    INTCON,
    INTTK,
    PLUS
};
```

这些不是我随便起的，而是老师要求最终输出的“单词类别码”。

### 标识符和常量

| 类别码 | 来源 | 含义 |
|---|---|---|
| `IDENFR` | Ident | 标识符，例如变量名、函数名 |
| `INTCON` | Integer Constant | 整数常量 |
| `CHARCON` | Character Constant | 字符常量 |
| `STRCON` | String Constant | 字符串常量 |

这里：

```text
INT  = Integer
CHAR = Character
STR  = String
CON  = Constant
```

`IDENFR` 是课程文档指定的固定类别码。它不是 C++ 的标准命名，不需要自己改成 `IDENTIFIER`，否则输出可能不符合评测要求。

### 关键字

关键字通常是：

```text
关键字英文 + TK
```

其中 `TK` 可以理解为 Token。

| 源代码 | 类别码 |
|---|---|
| `int` | `INTTK` |
| `char` | `CHARTK` |
| `void` | `VOIDTK` |
| `if` | `IFTK` |
| `else` | `ELSETK` |
| `while` | `WHILETK` |
| `main` | `MAINTK` |
| `return` | `RETURNTK` |

例如：

```text
RETURN + TK = RETURNTK
```

### 运算符

运算符类别码通常是英文含义的缩写：

| 符号 | 类别码 | 英文含义 |
|---|---|---|
| `+` | `PLUS` | plus |
| `-` | `MINU` | minus |
| `*` | `MULT` | multiply |
| `/` | `DIV` | divide |
| `%` | `MOD` | modulo |
| `=` | `ASSIGN` | assignment |
| `==` | `EQL` | equal |
| `!=` | `NEQ` | not equal |
| `<` | `LSS` | less |
| `<=` | `LEQ` | less or equal |
| `>` | `GRE` | greater |
| `>=` | `GEQ` | greater or equal |
| `!` | `NOT` | logical not |
| `&&` | `AND` | logical and |
| `||` | `OR` | logical or |

例如：

```text
NEQ = Not EQual
LEQ = Less or EQual
GEQ = Greater or EQual
```

### 括号和标点

| 符号 | 类别码 | 含义 |
|---|---|---|
| `;` | `SEMICN` | semicolon |
| `,` | `COMMA` | comma |
| `:` | `COLON` | colon |
| `(` | `LPARENT` | left parenthesis |
| `)` | `RPARENT` | right parenthesis |
| `[` | `LBRACK` | left bracket |
| `]` | `RBRACK` | right bracket |
| `{` | `LBRACE` | left brace |
| `}` | `RBRACE` | right brace |

这里要区分三种括号：

```text
parenthesis  ()
bracket      []
brace        {}
```

前面的 `L` 和 `R` 分别表示：

```text
L = Left
R = Right
```

因此：

```text
LPARENT = 左圆括号
RBRACK  = 右方括号
LBRACE  = 左花括号
```

## 二、我们自己写的变量名

这些名字不是老师规定的，只是为了让代码容易理解。

### `source`

```cpp
std::string source;
```

表示源代码：

```text
source code → source
```

它里面保存整个 `testfile.txt`。

### `pos`

```cpp
std::size_t pos = 0;
```

`pos` 是 `position` 的缩写，表示当前扫描位置。

例如：

```text
int age;
    ^
    pos
```

也可以叫：

```cpp
currentPosition
```

但 `pos` 更简洁。

### `line`

```cpp
int line = 1;
```

表示当前行号，因为错误输出需要行号。

### `lexeme`

```cpp
std::string lexeme;
```

`lexeme` 是词法分析里的专业术语，中文一般叫“词素”。

例如：

```c
int age = 18;
```

其中：

```text
Token类别       lexeme
INTTK           "int"
IDENFR          "age"
ASSIGN          "="
INTCON          "18"
SEMICN          ";"
```

`TokenType` 表示这个单词属于哪一类，`lexeme` 表示源代码里实际写了什么。

```c

```

`age` 和 `number` 的类型都是：

```cpp

```

但词素分别是：

```text
"age"
"number"
```

### `tokens`

```cpp
std::vector<Token> tokens;
```

复数形式表示保存了很多个 Token。

```text
token   一个Token
tokens  多个Token
```

### `current`

```cpp
char current = source[pos];
```

表示当前正在处理的字符。

### `peek`

```cpp
char peek();
```

`peek` 的意思是“偷看一眼”。它查看当前字符，但不移动位置。

### `peekNext`

```cpp
char peekNext();
```

查看下一个字符，但不移动位置。

这个函数用于判断：

```text
= 还是 ==
/ 还是 //
< 还是 <=
```

### `advance`

```cpp
char advance();
```

表示读取当前字符，同时把位置向后移动：

```cpp
char Lexer::advance() {
    return source[pos++];
}
```

### `match`

```cpp
bool match(char expected);
```

判断当前位置是不是期望的字符。如果匹配，就把它消费掉。

```cpp
if (match('=')) {
    // 当前是第二个等号，识别出 ==
}
```

### `scan`

```cpp
void scan();
```

表示扫描整个源代码。

### `scanOneToken`

```cpp
void scanOneToken();
```

表示尝试扫描一个 Token。

### `addToken`

```cpp
void addToken(...);
```

表示把识别出的 Token 放进：

```cpp
std::vector<Token> tokens;
```

## 三、整体命名规律

我采用的是：

```text
类和类型：大驼峰
变量和函数：小驼峰
枚举值：老师规定的大写类别码
```

例如：

```cpp
class Lexer;              // 类：大驼峰
struct Token;             // 结构体：大驼峰
enum class TokenType;     // 类型：大驼峰

std::string source;       // 变量：小写
int currentLine;          // 变量：小驼峰
void scanOneToken();      // 函数：小驼峰

TokenType::INTTK;         // 枚举值：规定的类别码
TokenType::IDENFR;
```

最重要的是：`INTTK`、`IDENFR`、`SEMICN` 这些名称必须和作业要求一致；`source`、`pos`、`scan()` 等内部名称则可以根据自己的习惯调整。
