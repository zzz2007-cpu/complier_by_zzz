**1. 先明确：语义分析在现有程序中做什么**

Parser 判断“这段代码符合哪条文法”，语义分析判断“这些名字和类型能否这样使用”。

例如 `a = f(x);` 已经可以生成语法树，但还需要检查：

- `a`、`f`、`x` 是否已经定义。
- `a` 是否为可以修改的变量，`f` 是否确实是函数。
- 参数数量、参数类型是否匹配。
- `f` 的返回类型是否能赋给 `a`。


**5. 错误检查按依赖顺序实现**

现有阶段保留 `a、i、j、k`，新增阶段负责其余错误。课程 PDF 第 12～17 页是具体依据。

| 顺序 | 错误码 | 实现重点 |
|---|---|---|
| 第一批 | `b` 重定义、`c` 未定义、`h` 修改常量 | 建立并查询符号表 |
| 第二批 | `d` 参数个数不匹配、`e` 类型不匹配 | 函数签名和表达式类型推导 |

| 第四批 | `l` printf 数量不匹配 | 解析格式占位符 |
| 第五批 | `m` 非法 break/continue、`n` 重复 case/default | 循环和 switch 上下文 |

几个必须按本课程处理的细节：

- **`int` 和 `char` 不能隐式混用。** `char + char` 仍是 `char`；显式转换后按目标类型检查。
- **`e` 不只是函数参数错误。** 还覆盖混合运算、赋值、返回值、数组下标、函数与变量误用、case 类型、printf 类型等。
- **数组名和数组元素要区分。** `a` 可以作为数组实参，`a[i]` 是标量；下标必须是 `int`，标量不能使用下标。
- **`g` 不需要控制流分析。** 检查函数体最外层最后一句是否为 return，报错位置是函数结尾的 `}`；不能用“函数内部任意地方出现过 return”代替。
- **printf 数量与类型分开检查。** 数量不匹配是 `l`，`%d/%c/%s` 与 `int/char/char[]` 类型不匹配是 `e`。
- **break 和 continue 的允许范围不同。** break 可在 while 或 switch 中；continue 必须处于 while 中。
- 每个 switch 单独保存 case 值集合和是否出现 default，嵌套 switch 不能共用集合。字符常量应解码后比较值。
- 重定义的函数仍要继续检查函数体；未定义名字则返回内部错误状态，避免据此再制造参数、运算或赋值类型错误。

函数按源码顺序处理：先登记当前函数及其签名，再检查函数体，既支持自身递归，也符合“作用域从声明处开始”的要求。

运行时库需要预置签名供调用检查，但不输出其符号，也不应让内建参数占用用户作用域编号。

**符号表就是编译器维护的一份“名字登记册”：记录程序里声明了哪些名字，以及每个名字代表什么。**

比如这段代码：

```cpp
const int limit = 10;
int count;

int add(int x) {
    int result;
    result = x + count;
    return result;
}
```

读到这些声明时，编译器会登记：

| 名字 | 是什么 | 类型 | 所属作用域 |
|---|---|---|---|
| `limit` | 常量 | int | 全局 |
| `count` | 变量 | int | 全局 |
| `add` | 函数 | 返回 int，接受一个 int 参数 | 全局 |
| `x` | 形参 | int | add 函数内部 |
| `result` | 变量 | int | add 函数内部 |

**遇到声明就登记，遇到使用就查表。**

当分析到：

```cpp
result = x + count;
```

编译器通过查表知道：

- `result` 已声明，而且是可以赋值的变量。
- `x` 是当前函数的参数，类型为 int。
- `count` 是全局变量，类型也是 int。

所以这条语句的名字和类型都没问题。

如果写成：

```cpp
limit = 20;
```

语法上仍然是合法的“左值 = 表达式”，但查表发现 `limit` 是常量，就能报“不能修改常量”的错误。

如果写成：

```cpp
result = missing + 1;
```

查不到 `missing`，就能报“未定义的名字”。

**作用域决定了查哪张表。** 可以先想成每个作用域都有自己的登记册：先查当前层，找不到再向外查。因此不同函数可以各有一个叫 `x` 的变量，它们不是同一个符号。

和你已有结构的区别是：

| 结构 | 回答的问题 |
|---|---|
| Token | 这个单词是什么？例如标识符 `count` |
| 语法树 | 这个单词出现在什么结构里？例如加法的右操作数 |
| 符号表 | 这个名字指向哪个声明？它是什么类型、能不能修改？ |

在实现上，**一条登记记录就是一个 `Symbol`，管理这些记录的结构就是符号表**。它不是程序运行时保存变量当前数值的地方；当前阶段最先需要记录的是：名字、类型、类别和所属作用域。

## 一、符号表需要记录什么

不要直接把 `Int`、`ConstInt`、`StaticIntArray` 当成内部类型。它们是最终输出名称，内部应该把几个属性分开记录。

### 1. 基本类型

```cpp
enum class BaseType
{
    Int,
    Char,
    Void
};
```

### 2. 符号类别

```cpp
enum class SymbolKind
{
    Variable,
    Constant,
    Function,
    Parameter
};
```

### 3. 表达式或参数的类型

后续类型检查主要关心五种类型：

```text
int
char
int[]
char[]
void
```

因此可以设计：

```cpp
struct SemanticType
{
    BaseType baseType;
    bool isArray;
};
```

例如：

```text
int a;       → { Int, false }
char text[]; → { Char, true  }
void func(); → { Void, false }
```

### 4. 一条符号记录

`Symbol` 建议至少包含：

```cpp
struct Symbol
{
    string name;                  // 名字
    SymbolKind kind;              // 变量、常量、函数、形参
    SemanticType type;            // int、char、int[]、char[]
    bool isStatic;                // 是否为静态变量
    int scopeId;                  // 所属作用域编号
    int line;                     // 声明所在行
    vector<SemanticType> params;  // 仅函数使用
};
```

各字段的用途如下：

| 字段 | 现在的用途 | 后续用途 |
|---|---|---|
| `name` | 输出和查找 | 未定义、重定义检查 |
| `kind` | 区分变量、常量、函数、形参 | 常量赋值、函数变量误用 |
| `type` | 输出符号类型 | 表达式类型检查 |
| `isStatic` | 输出 `StaticInt` 等 | 后续代码生成 |
| `scopeId` | 输出作用域编号 | 作用域管理 |
| `line` | 报错位置 | 重定义错误 `b` |
| `params` | 暂时不输出 | 参数个数和类型检查 `d/e` |

后续可能增加数组长度、常量值、中间代码地址等信息，但第一步不用急着写。

## 二、作用域需要什么结构

每个 `{...}` 语句块都会产生一个作用域。建议设计：

```cpp
struct Scope
{
    int id;
    int parentId;

    vector<Symbol> symbols;
    unordered_map<string, size_t> nameIndex;
};
```

这里同时保留两个容器是有原因的：

- `symbols` 保持声明顺序，方便输出；
- `nameIndex` 快速判断当前层是否已经有同名符号。

不能只使用 `unordered_map<string, Symbol>`，因为它的遍历顺序不等于声明顺序，而课程要求同一作用域内按声明顺序输出。

所有作用域可以由符号表统一保存：

```cpp
vector<Scope> scopes;
int currentScopeId;
```

注意：

- 全局作用域编号是 `1`；
- 每次进入新作用域，编号递增；
- 离开后编号不能复用；
- `parentId` 用于从当前层逐级向外查找；
- 已退出的作用域仍然保存在 `scopes` 中，因为最后还要输出其中的符号。

## 六、函数的处理逻辑

例如：

```cpp
int add(int a, char b[]) {
    int result;
}
```

推荐按以下顺序处理：

```text
1. 读取函数返回类型：int
2. 读取函数名：add
3. 提取形参类型：[int, char[]]
4. 将函数 add 登记到当前作用域，也就是全局作用域
5. 进入函数体作用域
6. 将形参 a、b 登记到这个函数体作用域
7. 遍历函数体中的声明和嵌套语句块
8. 离开函数体作用域
```

函数必须在分析函数体之前登记，这样递归调用能够查到自身。

即使函数发生重定义错误 `b`，课程仍要求继续分析它的函数体，所以不能因为 `define()` 返回 `false` 就直接跳过整个函数。

## 七、函数参数和函数体属于同一作用域

这是最容易写错的地方。

对于：

```cpp
int f(int x) {
    int y;
}
```

正确结果是：

```text
x 和 y 属于同一个作用域
```

因此不能这样做：

```text
进入函数作用域
登记参数
visitBlock 又进入一次新作用域   ← 多进入了一层
```

可以让 `visitBlock` 接收一个控制参数：

```text
visitBlock(block, createScope)
```

于是：

```text
普通嵌套 Block：
    visitBlock(block, true)

函数最外层 Block：
    先进入函数作用域
    登记参数
    visitBlock(block, false)
    离开函数作用域
```

`main` 也要创建函数体作用域，只是不把 `main` 本身加入符号表。

## 八、普通嵌套块的处理

例如：

```cpp
int main() {
    int a;

    {
        int b;
    }

    {
        int c;
    }
}
```

作用域应当是：

```text
作用域 1：全局
作用域 2：main 函数体，包含 a
作用域 3：第一个嵌套块，包含 b
作用域 4：第二个嵌套块，包含 c
```

作用域编号是进入顺序，不是嵌套深度。因此两个并列块不能都叫作用域 `3`。

## 九、符号登记的整体伪代码

```text
    进入新作用域
    遍历其中的声明和语句
    离开作用域

```

`SymbolKind` 表示“这个名字是什么”，最终输出名称还要结合 `type` 和 `isStatic` 决定。

### `Variable`

普通变量：

| `type` | `isStatic` | 输出 |
|---|---:|---|
| `Int` | false | `Int` |
| `Char` | false | `Char` |
| `IntArray` | false | `IntArray` |
| `CharArray` | false | `CharArray` |
| `Int` | true | `StaticInt` |
| `Char` | true | `StaticChar` |
| `IntArray` | true | `StaticIntArray` |
| `CharArray` | true | `StaticCharArray` |

例如：

```cpp
int a;              // Int
char text[10];      // CharArray
static int count;   // StaticInt
```

### `Constant`

| `type` | 输出 |
|---|---|
| `Int` | `ConstInt` |
| `Char` | `ConstChar` |
| `IntArray` | `ConstIntArray` |
| `CharArray` | `ConstCharArray` |

例如：

```cpp
const int size = 10;       // ConstInt
const char text[10] = {};  // ConstCharArray
```

常量不会带 `static`。

### `Function`

函数根据返回类型输出：

| `type` | 输出 |
|---|---|
| `Int` | `IntFunc` |
| `Char` | `CharFunc` |
| `Void` | `VoidFunc` |

函数不能是数组类型。`main` 不加入符号表，因此不输出 `main`。

### `Parameter`

形参没有独立的输出名称，按照普通变量输出：

| `type` | 输出 |
|---|---|
| `Int` | `Int` |
| `Char` | `Char` |
| `IntArray` | `IntArray` |
| `CharArray` | `CharArray` |

例如：

```cpp
int f(int a, char text[])
```

符号表中：

```text
a    Parameter + Int        → Int
text Parameter + CharArray  → CharArray
```

因此 `getOutputTypeName()` 的判断顺序可以是：

```text
如果是 Function：
    根据返回类型输出 XxxFunc

否则如果是 Constant：
    输出 Const + 类型名称

否则如果是 Variable 且 isStatic：
    输出 Static + 类型名称

否则：
    直接输出类型名称
```

`Parameter` 会自然进入最后一种情况。`Invalid` 是内部错误类型，不应该写入 `symbol.txt`。

循环两次不是必须的，只是为了把两个任务分开：

1. 第一遍先收集整条声明的公共信息：`static` 和 `BType`。
2. 第二遍使用这些信息创建每个 `VarDef` 的符号。

例如：

```cpp
static int a, b, c[10];
```

其中：

```text
isStatic = true
baseType = Int
```

是 `a`、`b`、`c` 共用的信息。

不过你的 Parser 已经保证 `VarDecl` 子节点顺序为：

```text
[static] → BType → VarDef → ... → ;
```

因此完全可以只循环一次：

```cpp
bool isStatic = false;
BaseType baseType = BaseType::Invalid;

for (const SyntaxNode &child : node.children)
{
    if (isTokenType(child, TokenType::STATICTK))
    {
        isStatic = true;
    }
    else if (isSyntaxType(child, SyntaxType::BType))
    {
        baseType = readBType(child);
    }
    else if (isSyntaxType(child, SyntaxType::VarDef))
    {
        // 此时 static 和 BType 已经读取完成
        // 根据 child 创建 Symbol
    }
}
```

处理到 `VarDef` 时，前面的 `BType` 一定已经出现，所以 `baseType` 已经有值。

两种方式区别是：

```text
两次循环：思路更分明，不依赖处理顺序，但重复遍历
一次循环：更精炼，依赖语法树严格保持文法顺序
```

你当前语法树就是 Parser 按顺序建立的，所以我建议直接使用一次循环。只需要在处理 `VarDef` 前确认：

```cpp
baseType != BaseType::Invalid
```

另外，判断数组必须针对当前这个 `VarDef` 的 `children`，不能扫描整个 `VarDecl`，否则其中只要有一个数组，就可能把同一条声明里的所有变量都误判为数组。
