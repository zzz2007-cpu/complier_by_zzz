## AST 结构

你的 Parser 把左递归改成了嵌套树：

| 节点 | 子节点形状 |
|---|---|
| `Exp` | `[AddExp]` |
| `AddExp` | `[MulExp]` 或 `[AddExp, 运算符, MulExp]` |
| `MulExp` | `[UnaryExp]` 或 `[MulExp, 运算符, UnaryExp]` |
| `UnaryExp` | `PrimaryExp`、一元运算、函数调用或显式转换 |

因此不能简单遍历所有孩子，要分别处理 `children[0]` 和 `children[2]`。

## 类型规则

我核对了本地[课程 PDF](/home/zzz2007-cpu/projects/compiler/docs/2026编译技术实验文法定义及相关说明.pdf)：

- `int` 和 `char` 不允许隐式混合运算。
- `Int op Int → Int`
- `Char op Char → Char`
- 数组和 `void` 不能参加普通算术运算。
- 显式转换后，以目标类型参加运算。
- 子表达式已经是 `Invalid` 时，不再追加新的 `e`，避免连锁报错。

## 依次实现这四层

### 1. `visitExp`

职责非常简单：

```text
找到直接子节点 AddExp
返回 visitAddExp(AddExp)
找不到则返回 Invalid
```

不要在这一层做类型判断。

### 2. `visitAddExp`

分两种形状。

单孩子：

```text
AddExp
└── MulExp
```

直接返回 `visitMulExp(children[0])`。

三个孩子：

```text
AddExp
├── AddExp
├── PLUS / MINU
└── MulExp
```

处理顺序：

1. 左边调用 `visitAddExp(children[0])`。
2. 右边调用 `visitMulExp(children[2])`。
3. 任意一边是 `Invalid`，直接返回 `Invalid`。
4. 两边必须都是标量，即 `isScalarType(type)` 为真。
5. 两边类型必须完全相同。
6. 不满足时，在运算符所在行记录 `TypeMismatch`，返回 `Invalid`。
7. 满足时返回左边类型。

也就是说：

```text
Int  + Int  → Int
Char + Char → Char
Int  + Char → e, Invalid
数组 + 数组 → e, Invalid
```

### 3. `visitMulExp`

逻辑与 `visitAddExp` 完全相同，只是节点形状变成：

```text
[UnaryExp]
```

或者：

```text
[MulExp, MULT/DIV/MOD, UnaryExp]
```

左边递归调用 `visitMulExp`，右边调用 `visitUnaryExp`。

先不要急着提取公共函数。两层都写通、验证正确后再消除重复，会更容易排查 AST 访问错误。

### 4. `visitUnaryExp`

需要区分四种形式。

#### 普通基本表达式

如果找到 `PrimaryExp`：

```text
return visitPrimaryExp(child)
```

#### 一元 `+`、`-`、`!`

形状是：

```text
[UnaryOp, UnaryExp]
```

规则：

- 先递归得到右侧类型。
- `Invalid` 直接向上传递。
- 数组、`void` 产生 `e`。
- `+`、`-` 保留操作数类型。
- `!` 的结果为 `Int`。

#### 显式类型转换

形状是：

```text
[LPARENT, BType, RPARENT, UnaryExp]
```

规则：

1. 用 `readBType(children[1])` 得到目标类型。
2. 递归分析 `children[3]`。
3. 被转换对象只能是 `Int` 或 `Char`。
4. 合法时返回目标类型。

例如：

```text
(int)'a' → Int
(char)1  → Char
(int)arr → e
```

#### 函数调用

当前阶段先完成最小处理：

1. 用函数名查符号表。
2. 找不到：记录 `c`，返回 `Invalid`。
3. 找到了但不是 `Function`：记录 `e`，返回 `Invalid`。
4. 是函数：访问实参中的每个 `Exp`，最后返回函数的返回类型。

参数数量 `d` 和参数类型 `e` 留到下一步集中实现。

这里特判 `Int`，检查的是“数组下标表达式的类型”，不是数组元素类型。

课程规范明确要求：数组下标只能是 `int`，`char` 不能隐式作为下标，因为本项目中 `int` 和 `char` 是严格不同的类型。

例如：

```c
char arr[10];
int i;
char c;

arr[i];       // 合法，下标是 Int，表达式结果是 Char
arr[c];       // e：下标是 Char
arr[(int)c];  // 合法：显式转换成 Int
```

执行过程是：

```text
visitExp(index)                 得到下标类型
        ↓
必须是 Int
        ↓
getArrayElementType(symbol.type) 得到元素类型
```

所以对于 `char arr[10]`：

- 下标必须是 `Int`
- `getArrayElementType(CharArray)` 返回 `Char`

你当前判断还有一个小问题：发现下标不是 `Int` 后只记录错误，却继续返回元素类型。更合理的是：

```cpp
if (indexType == BaseType::Invalid)
{

}

if (indexType != BaseType::Int)
{
    errors.emplace_back(ErrorType::TypeMismatch, token.line);

```

这样 `arr[c]` 不会在报错后仍被当作一个正常的 `Char` 表达式继续向上传递。

简单说：这里判断的不是“数组里面装的是 int 还是 char”，而是“你用什么类型的数字去找数组元素”。

例如：

```c
char arr[10];
int i = 2;
```

`arr` 里面装的是 `char`，但访问它时：

```c
arr[i]
```

分成两部分：

```text
arr  → CharArray，数组里存的是 char
i    → Int，用来表示访问第几个元素
结果 → Char，取出来的是 char
```

所以：

```cpp
BaseType indexType = visitExp(*index);
```

这里的 `indexType` 是 `i` 的类型。课程规定数组下标必须是 `Int`，因此判断：

```cpp

```

而这一句：

```cpp
BaseType elementType = getArrayElementType(symbol->type);
```

才是在判断数组里装的是什么：

```text
IntArray  → Int
CharArray → Char
```

完整例子：

```c
char arr[10];

-a
+a
!a

UnaryExp
├── UnaryOp
└── UnaryExp

UnaryExp
├── LPARENT
├── BType
├── RPARENT

UnaryExp
├── children[0]: LPARENT Token
├── children[1]: BType
├── children[2]: RPARENT Token
└── children[3]: UnaryExp
```

`children[3]` 是非终结符 `UnaryExp`，不能调用 `getToken()`。

实际测试：

```c
int main() {
    int a[2];
    (int)a;
    return 0;
}
```

运行结果：

```text
std::bad_variant_access
退出码 134
```

这里应从转换位置的 Token 获取行号，例如：

```cpp
node.children[0].getToken().line
```

也就是左括号所在行。也可以从 `BType` 的终结符孩子取行号，但不能直接读取 `children[3]`。

这段还可以简化为：

```text
changedType == Invalid
    → 下层已有错误，直接返回 Invalid

isScalarType(changedType)
    → 返回 targetType

其他类型
    → 记录 e，返回 Invalid
```

## 已修复并验证的部分

以下部分现在是正确的：

- `PrimaryExp` 使用 `isSyntaxType()` 安全分派。
- 显式转换和函数调用使用 `isTokenType()`。
- `!Int`、`!Char` 都返回 `Int`。
- `AddExp` 左边访问 `AddExp`，右边访问 `MulExp`。
- `MulExp` 左边访问 `MulExp`，右边访问 `UnaryExp`。
- Add/Mul 都从 `children[1]` 获取运算符行号。
- `visitUnaryExp()` 所有路径都有返回值。
- `visitStmt()` 已接入直接孩子 `Exp`。
- 函数实参能够收集类型并检查 `d/e`。
