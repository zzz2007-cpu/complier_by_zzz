语法分析的本质是：

> **把词法分析得到的一串 Token，按照 SysY 文法，组装成有层次的程序结构。**

例如源代码：

```c
int x = 1 + 2;
```

词法分析只会得到：

```text
INTTK int
IDENFR x
ASSIGN =
INTCON 1
PLUS +
INTCON 2
SEMICN ;
```

它只知道每个单词是什么，却不知道它们组合起来表示什么。

语法分析则要进一步识别出：

```text
1、2                 → Number
1、2                 → PrimaryExp
1 + 2                → AddExp
1 + 2                → Exp
x = 1 + 2;           → 变量定义/声明
int x = 1 + 2;       → VarDecl
```

可以把两者理解成：

- 词法分析：把字符切成“单词”。
- 语法分析：判断这些单词能否组成合法的“句子”，并找出句子的结构。
- 后续语义分析：判断这个句子的含义是否合理，例如变量是否定义、函数参数是否匹配。

你们这次任务具体要完成四件事：

1. 接收 `Lexer` 产生的 `vector<Token>`。
2. 按文法识别 `CompUnit`、`Stmt`、`AddExp` 等非终结符。
3. 用递归下降法建立语法树。
4. 遇到缺少 `;`、`)`、`]` 等情况时记录错误，并继续分析后面的代码。

所谓递归下降，就是通常让一个文法成分对应一个函数：

```cpp
parseCompUnit();
parseVarDecl();
parseStmt();
parseExp();
parseAddExp();
parseMulExp();
```

比如分析加法表达式的大致逻辑是：

```text
parseAddExp
    先分析一个 MulExp
    只要后面还有 + 或 -
        读取运算符
        再分析一个 MulExp
```

因此，语法分析器的核心状态通常只有：

```cpp
vector<Token> tokens; // 词法分析结果
size_t pos;           // 当前看到第几个 Token
```

它反复做三种动作：

```text
看当前 Token → 判断应走哪条文法规则 → 消耗对应 Token
```

课程要求的 `parser.txt` 中这些内容：

```text
INTCON 1
<Number>
<PrimaryExp>
<UnaryExp>
<MulExp>
<AddExp>
<Exp>
```

只是为了让评测系统检查你的分析过程。**真正有价值的产物是语法树**，后面的符号表、类型检查、中间代码生成都会继续使用它。

一句话总结：

> **语法分析就是给扁平的 Token 序列“搭骨架”，还原出源程序的层次结构，并判断它是否符合文法。**

你们当前的 `Lexer` 已经负责制造 Token；下一阶段的 `Parser` 就负责读取这些 Token，而不是重新读取和拆分源代码。

## 8. 助手

时间：2026-09-30 12:26:48

语法树就是：

> **把程序“谁包含谁、谁和谁组合、先算什么”这些关系，用一棵树保存下来。**

源代码本来是一条平铺的字符序列，但程序本身具有明显的层次结构，所以用树来表示最自然。

例如：

```c
int x = 1 + 2 * 3;
```

词法分析得到的只是一条 Token 队列：

```text
INTTK IDENFR ASSIGN INTCON PLUS INTCON MULT INTCON SEMICN
 int     x      =       1     +      2     *      3      ;
```

仅看这个数组，它们都是平级的。但真实结构是：

```text
变量声明
├── 类型：int
├── 变量名：x
└── 初始值
    └── 加法表达式
        ├── 数字：1
        ├── 运算符：+
        └── 乘法表达式
            ├── 数字：2
            ├── 运算符：*
            └── 数字：3
```

这棵树直接说明：

```text
1 + (2 * 3)
```

而不是：

```text
(1 + 2) * 3
```

## 为什么必须有“树”

因为程序天然就是一层套一层的。

例如：

```c
if (a > 0) {
    while (b > 0) {
        b = b - 1;
    }
}
```

它的结构是：

```text
if语句
├── 条件：a > 0
└── if语句块
    └── while语句
        ├── 条件：b > 0
        └── while语句块
            └── 赋值语句：b = b - 1
```

这里存在明显的父子关系：

- `if` 包含一个条件和一个语句块。
- 语句块包含 `while`。
- `while` 又包含条件和语句块。
- 最内层语句块包含赋值语句。

普通数组适合表达“先后顺序”，树更适合表达“嵌套和从属关系”。

## 语法树以后有什么用

语法分析完成后，后面的编译阶段不需要反复研究原始代码，而是直接遍历语法树。

### 检查语义

看到：

```text
赋值语句
├── 左边：x
└── 右边：表达式
```

语义分析可以检查：

- `x` 有没有定义？
- `x` 是不是常量？
- 左右两边类型是否兼容？

### 生成代码

对于：

```c
1 + 2 * 3
```

按照语法树从底向上处理：

```text
先计算 2 * 3
再计算 1 + 结果
```

因此可以生成类似：

```text
t1 = 2 * 3
t2 = 1 + t1
x = t2
```

### 确定作用域

对于：

```c
{
    int x;
    {
        int x;
    }
}
```

语法树能够保存两个语句块的嵌套关系，后续才能知道两个 `x` 属于不同作用域。

## 语法树节点保存什么

一个节点通常需要保存：

```cpp
struct SyntaxNode {
    SyntaxType type;               // 这个节点是什么语法成分
    vector<SyntaxNode*> children;  // 它包含哪些子成分
};
```

例如 `1 + 2 * 3` 可以表示为：

```text
AddExp
├── MulExp
│   └── Number(1)
├── PLUS(+)
└── MulExp
    ├── Number(2)
    ├── MULT(*)
    └── Number(3)
```

其中：

- `AddExp`、`MulExp` 是非终结符节点。
- `1`、`+`、`2`、`*`、`3` 是 Token 叶子节点。
- `children` 保存父子关系。

## 语法树和 AST 的区别

课程目前要求的通常更接近“完整语法树”：

```text
AddExp
└── MulExp
    └── UnaryExp
        └── PrimaryExp
            └── Number
                └── INTCON 1
```

它完整保留文法分析过程，方便输出：

```text
INTCON 1
<Number>
<PrimaryExp>
<UnaryExp>
<MulExp>
<AddExp>
```

以后生成代码时，可以把这些中间层精简成抽象语法树 AST：

```text
整数：1
```

所以当前阶段先理解为：

> **语法树是 Token 的分层组织形式。叶子是具体单词，父节点是这些单词组成的语法结构。**

没有树，我们只有“程序里依次出现了什么”；有了树，我们才知道“这个程序到底表达了什么结构”。

不建议“每一种语法写一个子类”。对这次作业来说会产生三十多个类，代码很散，也没有必要。

更合适的设计是：

> **一个统一的语法树节点 `SyntaxNode`，加一个负责分析的 `Parser` 类；每一种语法成分对应 `Parser` 里的一个函数。**

整体关系是：

```text
Lexer
  │ 产生 vector<Token>
  ▼
Parser
  │ 调用 parseCompUnit、parseStmt、parseExp...
  ▼
SyntaxNode 语法树
```

## 一、统一的语法树节点

先用枚举表示语法成分：

```cpp

    VarDecl,
    ConstDef,
    VarDef,

    MainFuncDef,
    Block,
    Stmt,
    CaseStmt,

    LVal,

    LAndExp,
    LOrExp,

    // 其余语法类型继续补充
};
```

然后定义一种统一节点：

```cpp
#include <memory>
#include <optional>
#include <vector>

struct SyntaxNode {
    // 非终结符节点使用 syntaxType
    std::optional<SyntaxType> syntaxType;

    // Token 叶子节点使用 token
    std::optional<Token> token;

    std::vector<std::unique_ptr<SyntaxNode>> children;
};
```

节点分两种。

Token 叶子节点：

```text
INTCON 123
PLUS +
IDENFR x
```

语法成分节点：

```text
<Number>
<AddExp>
<Stmt>
<FuncDef>
```

判断方式就是：

```cpp
if (node.token.has_value()) {
    // Token叶子
} else {
    // 语法成分
}
```

## 二、一个 Parser 类

`Parser` 保存 Token 数组和当前位置：

```cpp
class Parser {
private:
    const std::vector<Token>& tokens;
    std::size_t pos = 0;

public:
    explicit Parser(const std::vector<Token>& tokens);

    std::unique_ptr<SyntaxNode> parse();
};
```

还需要几个公共辅助函数：

```cpp
class Parser {
private:
    const std::vector<Token>& tokens;
    std::size_t pos = 0;

    bool isAtEnd() const;

    const Token& current() const;
    const Token& peek(std::size_t offset = 0) const;

    bool check(TokenType type) const;
    bool match(TokenType type);

    std::unique_ptr<SyntaxNode> consume(TokenType type);

    // 各种文法分析函数
    std::unique_ptr<SyntaxNode> parseCompUnit();
    std::unique_ptr<SyntaxNode> parseConstDecl();
    std::unique_ptr<SyntaxNode> parseVarDecl();
    std::unique_ptr<SyntaxNode> parseStmt();
    std::unique_ptr<SyntaxNode> parseExp();
    std::unique_ptr<SyntaxNode> parseAddExp();
    std::unique_ptr<SyntaxNode> parseMulExp();
    std::unique_ptr<SyntaxNode> parseUnaryExp();
    std::unique_ptr<SyntaxNode> parsePrimaryExp();
};
```


## 三、一个文法对应一个函数

例如：

```text
Number → IntConst | CharConst
```

可以写成：

```cpp
std::unique_ptr<SyntaxNode> Parser::parseNumber()
{
    auto node = std::make_unique<SyntaxNode>();
    node->syntaxType = SyntaxType::Number;

    if (check(TokenType::INTCON)) {
        node->children.push_back(consume(TokenType::INTCON));
    } else if (check(TokenType::CHARCON)) {
        node->children.push_back(consume(TokenType::CHARCON));
    }

    return node;
}
```

`consume()` 消耗一个 Token，并将它包装成叶子节点：

```cpp
std::unique_ptr<SyntaxNode> Parser::consume(TokenType expected)
{
    if (!check(expected)) {
        // 后续在这里进行错误处理
        return nullptr;
    }

    auto node = std::make_unique<SyntaxNode>();
    node->token = tokens[pos];
    pos++;

    return node;
}
```

## 四、文法函数互相调用

例如文法：

```text
PrimaryExp → '(' Exp ')' | LVal | Number
```

对应的分析思路：

```cpp
std::unique_ptr<SyntaxNode> Parser::parsePrimaryExp()
{
    auto node = std::make_unique<SyntaxNode>();
    node->syntaxType = SyntaxType::PrimaryExp;

    if (check(TokenType::LPARENT)) {
        node->children.push_back(consume(TokenType::LPARENT));
        node->children.push_back(parseExp());
        node->children.push_back(consume(TokenType::RPARENT));
    }
    else if (check(TokenType::INTCON) ||
             check(TokenType::CHARCON)) {
        node->children.push_back(parseNumber());
    }
    else if (check(TokenType::IDENFR)) {
        node->children.push_back(parseLVal());
    }

    return node;
}
```

这就是递归下降：

```text
parsePrimaryExp()
    └── parseExp()
            └── parseAddExp()
                    └── parseMulExp()
                            └── parseUnaryExp()
                                    └── parsePrimaryExp()
```

括号表达式会再次调用表达式分析，所以形成递归。

## 五、表达式需要处理优先级

例如：

```c
1 + 2 * 3
```

分析顺序应该是：

```text
parseAddExp
├── parseMulExp：1
├── PLUS
└── parseMulExp：2 * 3
```

因为 `MulExp` 位于 `AddExp` 的下一层，所以乘法自然比加法优先。

大致结构是：

```cpp
std::unique_ptr<SyntaxNode> Parser::parseAddExp()
{
    auto left = makeSyntaxNode(
        SyntaxType::AddExp,
        parseMulExp()
    );

    while (check(TokenType::PLUS) ||
           check(TokenType::MINU)) {
        auto parent = std::make_unique<SyntaxNode>();
        parent->syntaxType = SyntaxType::AddExp;

        parent->children.push_back(std::move(left));

        if (check(TokenType::PLUS)) {
            parent->children.push_back(consume(TokenType::PLUS));
        } else {
            parent->children.push_back(consume(TokenType::MINU));
        }

        parent->children.push_back(parseMulExp());
        left = std::move(parent);
    }

    return left;
}
```

这样 `1 + 2 + 3` 会形成左结合结构：

```text
AddExp
├── AddExp
│   ├── AddExp
│   │   └── 1
│   ├── +
│   └── 2
├── +
└── 3
```

这也有利于按照课程格式输出多个 `<AddExp>`。

## 六、推荐的文件划分

可以逐步整理为：

```text
src/
├── Token.h
├── Token.cpp
├── Lexer.h
├── Lexer.cpp
├── SyntaxNode.h
├── SyntaxNode.cpp
├── Parser.h
├── Parser.cpp
├── Error.h
├── Error.cpp
└── main.cpp
```

职责分别是：

```text
Token       保存单词类型和内容
Lexer       源代码 → Token数组
SyntaxNode  定义语法树节点
Parser      Token数组 → 语法树
Error       保存错误
main        串联整个过程并输出文件
```

你当前的 `Token` 结构体最好从 `Lexer.h` 移到 `Token.h`。因为 `Token` 不只是 Lexer 使用，Parser 和语法树也都需要它。

最终主流程大致是：

```cpp
Lexer lexer(source);
lexer.scan();

Parser parser(lexer.getTokens());
std::unique_ptr<SyntaxNode> root = parser.parse();

printParserTree(root);
printErrors();
```

所以最适合我们当前项目的结论是：

> **不用为每一种语法建立子类。建立一个通用节点类型，把不同语法成分写成 `SyntaxType`；再在一个 `Parser` 类中，为每条主要文法编写一个 `parseXXX()` 函数。**

这种结构足够清晰，也方便后面继续做语义分析和代码生成。

题目要求识别 **33 种语法类别（非终结符）**。它们不是 `INTTK`、`IDENFR` 这样的单词类别，而是若干 Token 组合形成的程序结构。

先认识文法符号：

- `{A}`：A 可以重复零次或多次。
- `[A]`：A 可以出现，也可以不出现。
- `A | B`：A、B 二选一。
- `'int'`：必须出现的具体 Token。

## 一、程序整体：1种

| 语法类别 | 中文 | 含义 |
|---|---|---|
| `CompUnit` | 编译单元 | 整个源程序，也是语法树的根节点。由全局声明、普通函数和最后的 `main` 函数组成。 |

文法：

```text
CompUnit → {Decl} {FuncDef} MainFuncDef
```

例如：

```c
int global;
int add(int a, int b) { return a + b; }
int main() { return 0; }
```

整个文件就是一个 `CompUnit`。

## 二、声明与定义：8种

| 语法类别 | 中文 | 含义 |
|---|---|---|
| `Decl` | 声明 | 对常量声明和变量声明的统一包装。 |
| `ConstDecl` | 常量声明 | 一整条 `const` 声明，可以一次声明多个常量。 |
| `BType` | 基本类型 | `int` 或 `char`。 |
| `ConstDef` | 常量定义 | 一条声明中的某一个常量，可以是普通常量或一维数组。 |
| `ConstInitVal` | 常量初值 | 常量等号右边的初始化内容。 |
| `VarDecl` | 变量声明 | 一整条变量声明，可以有 `static`，也可以一次声明多个变量。 |
| `VarDef` | 变量定义 | 一条声明中的某一个变量，可以带初始化，也可以不带。 |
| `InitVal` | 变量初值 | 变量等号右边的初始化内容。 |

它们的包含关系如下：

```text
Decl
├── ConstDecl
│   ├── BType
│   ├── ConstDef
│   └── ConstInitVal
└── VarDecl
    ├── BType
    ├── VarDef
    └── InitVal
```

例如：

```c
const int a = 10, b = 20;
```

结构是：

```text
ConstDecl
├── BType：int
├── ConstDef：a = 10
└── ConstDef：b = 20
```

例如：

```c
static char names[10] = "hello";
```

包含：

```text
VarDecl
├── static
├── BType：char
└── VarDef
    ├── names[10]
    └── InitVal："hello"
```

完整文法中，`ConstInitVal` 和 `InitVal` 都可能是：

- 单个表达式；
- `{...}` 数组初始化列表；
- `StringConst` 字符串初始化。

## 三、函数：5种

| 语法类别 | 中文 | 含义 |
|---|---|---|
| `FuncDef` | 普通函数定义 | 除 `main` 以外的函数定义。 |
| `MainFuncDef` | 主函数定义 | 固定形式的 `int main() {...}`。 |
| `FuncType` | 函数类型 | 函数返回类型，可以是 `void`、`int` 或 `char`。 |
| `FuncFParams` | 函数形参表 | 函数定义中圆括号里的全部形参。 |
| `FuncFParam` | 函数形参 | 形参表中的某一个参数。 |

例如：

```c
int add(int a, int b[]) {
    return a + b[0];
}
```

结构是：

```text
FuncDef
├── FuncType：int
├── 函数名：add
├── FuncFParams
│   ├── FuncFParam：int a
│   └── FuncFParam：int b[]
└── Block
```

注意两个相似概念：

- `FuncFParams`：函数定义时的**形参**，例如 `int a, int b`。
- `FuncRParams`：函数调用时的**实参**，例如 `add(x, 10)` 中的 `x, 10`。

## 四、语句块与语句：4种

| 语法类别 | 中文 | 含义 |
|---|---|---|
| `Block` | 语句块 | 一对 `{}` 以及里面的所有内容。 |
| `BlockItem` | 语句块项 | 语句块内部的一个项目，可以是声明，也可以是语句。 |
| `Stmt` | 语句 | 赋值、表达式、`if`、`while`、`return` 等可以执行的结构。 |
| `CaseStmt` | Case语句 | `switch` 中的一个 `case` 或 `default` 分支。 |

### Block和BlockItem

例如：

```c

}
```

```text

├── BlockItem
│   └── Decl：int x;
└── BlockItem
    └── Stmt：x = 10;
```


## 五、表达式：15种

| 语法类别 | 中文 | 含义 |
|---|---|---|
| `Exp` | 普通表达式 | 普通算术表达式，入口是 `AddExp`。 |
| `Cond` | 条件表达式 | `if`、`while` 等使用的条件，入口是 `LOrExp`。 |
| `LVal` | 左值表达式 | 变量或数组元素，表示一个可以被访问或赋值的位置。 |
| `PrimaryExp` | 基本表达式 | 括号表达式、左值或者数值。 |
| `Number` | 数值 | 整数常量或字符常量。 |
| `UnaryExp` | 一元表达式 | 基本表达式、函数调用、单目运算或显式类型转换。 |
| `UnaryOp` | 单目运算符 | `+`、`-`、`!`。 |
| `FuncRParams` | 函数实参表 | 调用函数时传入的表达式列表。 |
| `MulExp` | 乘除模表达式 | 处理 `*`、`/`、`%`。 |
| `AddExp` | 加减表达式 | 处理 `+`、`-`。 |
| `RelExp` | 关系表达式 | 处理 `<`、`>`、`<=`、`>=`。 |
| `EqExp` | 相等性表达式 | 处理 `==`、`!=`。 |
| `LAndExp` | 逻辑与表达式 | 处理 `&&`。 |
| `LOrExp` | 逻辑或表达式 | 处理 `||`。 |
| `ConstExp` | 常量表达式 | 必须能在编译期间求值的表达式。 |

### Exp

```text
Exp → AddExp
```

例如：

```c
1 + 2 * 3
```

这是普通算术表达式。根据本题文法，`Exp` 本身不包含 `<`、`&&` 等条件运算。

### Cond

```text
Cond → LOrExp
```

例如：

```c
a > 0 && b != 1
```

它用于：

```c
if (a > 0 && b != 1) {
}
```

### LVal

```text
LVal → Ident ['[' Exp ']']
```

包括：

```c
x
array[i]
```

“左值”表示一个有存储位置的对象，因此可以出现在赋值号左边：

```c
x = 10;

```

### PrimaryExp

包括：

```c
(1 + 2)  // 括号表达式
x        // LVal
123      // Number
'a'      // Number
```

### Number

只包括：

```text

CharConst
```

例如：

```c
123
'a'
'\n'
```

这里的 `Number` 是语法类别；`INTCON`、`CHARCON` 是词法类别。

### UnaryExp

一元表达式有四种主要形式：

```c
x                 // PrimaryExp
add(1, 2)         // 函数调用
-x                // UnaryOp UnaryExp
!flag             // UnaryOp UnaryExp
(int)ch           // 显式类型转换
(char)number      // 显式类型转换
```

### FuncRParams

例如：

```c
add(x, 10, array[i])
```

其中：

```text
x, 10, array[i]
```

整体是一个 `FuncRParams`，里面包含三个 `Exp`。

### 运算优先级

表达式类别的层次直接决定运算优先级，由低到高为：

```text
LOrExp       ||
└── LAndExp  &&
    └── EqExp        == !=
        └── RelExp   < > <= >=
            └── AddExp   + -
                └── MulExp   * / %
                    └── UnaryExp  +x -x !x (int)x
                        └── PrimaryExp
```

因此：

```c
a + b * c < d && e != f || g
```

会按照下面的顺序组合：

```text
a + (b * c)
(a + b * c) < d
e != f
((a + b * c) < d) && (e != f)
上面的结果 || g
```

### ConstExp

```text
ConstExp → AddExp
```

语法形式和普通算术表达式相似，但它必须能够在编译期算出结果。

合法例子：

```c
const int n = 10;
int array[n + 1];
```

这里 `n + 1` 是 `ConstExp`，因为 `n` 是常量。

## 29. 助手

时间：2026-09-30 12:45:57

对，递归下降语法分析最清晰的做法就是：

> **每一个非终结符基本对应一个 `parseXXX()` 识别函数。**

题目有33种语法类型，最稳妥的实现就是准备33个函数。但这些函数并不都复杂：有些只有几行，有些负责选择分支，有些负责循环解析。

不是建立33个类，而是：

```text
1个 Parser 类
+ 33个 parseXXX() 成员函数
+ 1种通用 SyntaxNode 节点
```

## 一、Parser整体工作方式

Parser保存：

```cpp
class Parser {
private:
    const std::vector<Token>& tokens;
    std::size_t pos = 0;
};
```

`pos` 表示当前正在分析哪个Token：

```text
INTTK int
IDENFR x
ASSIGN =
INTCON 10
SEMICN ;
       ↑
      pos
```

每个解析函数完成三件事：

1. 判断当前Token是否符合对应文法。
2. 消耗相应Token，并调用更小的语法分析函数。
3. 返回一个语法树节点。

统一形式是：

```cpp
std::unique_ptr<SyntaxNode> Parser::parseXXX()
{
    auto node = makeSyntaxNode(SyntaxType::XXX);

    // 分析子节点

    return node;
}
```

## 二、建议每种语法都写函数

### 程序入口

```cpp
parseCompUnit()
```

### 声明部分

```cpp
parseDecl()
parseConstDecl()
parseBType()
parseConstDef()
parseConstInitVal()
parseVarDecl()
parseVarDef()
parseInitVal()
```

### 函数部分

```cpp
parseFuncDef()
parseMainFuncDef()
parseFuncType()
parseFuncFParams()
parseFuncFParam()
```

### 语句部分

```cpp
parseBlock()
parseBlockItem()
parseStmt()
parseCaseStmt()
```

### 表达式部分

```cpp
parseExp()

parseFuncRParams()
parseMulExp()
parseAddExp()

parseEqExp()
parseLAndExp()
parseLOrExp()
parseConstExp()
```

这样函数名和文法名称一一对应，检查遗漏时很方便。

## 三、有些函数只是“转发”

例如：

```text
Exp → AddExp
```

对应函数非常简单：

```cpp
std::unique_ptr<SyntaxNode> Parser::parseExp()
{
    auto node = makeSyntaxNode(SyntaxType::Exp);
    node->addChild(parseAddExp());
    return node;
}
```

再如：

```text
Cond → LOrExp
```

对应：

```cpp
std::unique_ptr<SyntaxNode> Parser::parseCond()
{
    auto node = makeSyntaxNode(SyntaxType::Cond);
    node->addChild(parseLOrExp());
    return node;
}
```

虽然函数很短，也建议保留。因为：

- 语法树需要有 `<Exp>` 和 `<Cond>` 节点。
- `parser.txt` 需要输出对应名称。
- 后续语义分析可能需要区分普通表达式和条件表达式。

## 四、有些函数负责选择文法分支

例如：

```text
Decl → ConstDecl | VarDecl
```

可以根据当前Token选择：

```cpp
std::unique_ptr<SyntaxNode> Parser::parseDecl()
{
    auto node = makeSyntaxNode(SyntaxType::Decl);

    if (check(TokenType::CONSTTK)) {
        node->addChild(parseConstDecl());
    } else {
        node->addChild(parseVarDecl());
    }

    return node;
}
```

虽然 `<Decl>` 不输出，但它仍然表示文法中的选择关系。

再如：

```text
BlockItem → Decl | Stmt
```

需要判断当前位置是声明还是语句：

```cpp
std::unique_ptr<SyntaxNode> Parser::parseBlockItem()
{
    auto node = makeSyntaxNode(SyntaxType::BlockItem);

    if (isDeclStart()) {
        node->addChild(parseDecl());
    } else {
        node->addChild(parseStmt());
    }

    return node;
}
```

其中：

```cpp
bool Parser::isDeclStart() const
{
    return check(TokenType::CONSTTK) ||
           check(TokenType::STATICTK) ||
           check(TokenType::INTTK) ||
           check(TokenType::CHARTK);
}
```

## 五、有些函数负责循环

例如：

```text
FuncFParams → FuncFParam { ',' FuncFParam }
```

意思是先识别一个形参，后面可以继续出现多个：

```cpp
std::unique_ptr<SyntaxNode> Parser::parseFuncFParams()
{
    auto node = makeSyntaxNode(SyntaxType::FuncFParams);

    node->addChild(parseFuncFParam());

    while (check(TokenType::COMMA)) {
        node->addChild(consume(TokenType::COMMA));
        node->addChild(parseFuncFParam());
    }

    return node;
}
```

同样的模式还会用于：

- 多个变量定义；
- 多个常量定义；
- 多个函数参数；
- 数组初始化；
- 多条语句；
- 多个`case`；
- 表达式中的连续运算。

## 六、表达式不能直接照抄左递归

题目文法中有：

```text
AddExp → MulExp | AddExp ('+' | '-') MulExp
```

如果直接写：

```cpp
parseAddExp()
{
    parseAddExp(); // 无限递归
}
```

程序会不断调用自己，最终栈溢出。

实现时要理解成：

```text
AddExp → MulExp { ('+' | '-') MulExp }
```

也就是：

```cpp
std::unique_ptr<SyntaxNode> Parser::parseAddExp()
{
    auto left = makeSyntaxNode(
        SyntaxType::AddExp,
        parseMulExp()
    );

    while (check(TokenType::PLUS) ||
           check(TokenType::MINU)) {
        auto parent = makeSyntaxNode(SyntaxType::AddExp);

        parent->addChild(std::move(left));
        parent->addChild(consumeCurrent());
        parent->addChild(parseMulExp());

        left = std::move(parent);
    }

    return left;
}
```

这里采用左折叠，是为了让：

```c
a - b - c
```

形成：

```text
(a - b) - c
```

而不是：

```text
a - (b - c)
```

以下类型都要用类似循环处理：

```text
MulExp
AddExp
RelExp
EqExp
LAndExp
LOrExp
```

## 七、最复杂的是几个“需要判断”的位置

### 区分全局变量和函数

两者可能都以类型开头：

```c
int x;          // VarDecl
int add() {}    // FuncDef
int main() {}   // MainFuncDef
```

需要向后观察Token：

```text
int main (    → MainFuncDef
int add  (    → FuncDef
int x    ;    → VarDecl
int x    =    → VarDecl
int x    [    → VarDecl
```

可以设计：

```cpp
bool isMainFuncDef() const;
bool isFuncDef() const;
bool isDecl() const;
```

大致判断：

```cpp
bool Parser::isMainFuncDef() const
{
    return check(TokenType::INTTK) &&
           checkNext(TokenType::MAINTK);
}

bool Parser::isFuncDef() const
{
    return isFuncType(current().type) &&
           peek(1).type == TokenType::IDENFR &&
           peek(2).type == TokenType::LPARENT;
}
```

### 区分左值和函数调用

当前Token都是`IDENFR`：

```c
x          // LVal
array[i]   // LVal
add(1, 2)  // 函数调用
```

判断下一个Token：

```text
IDENFR LPARENT → 函数调用
其他情况       → LVal
```

### 区分赋值语句和表达式语句

例如：

```c
x = 10;    // 赋值语句
x + 10;    // 表达式语句
foo();     // 表达式语句
```

它们都可能从`IDENFR`开始，因此`parseStmt()`需要提前判断当前语句中是否存在属于当前层的赋值号。

可以设计：

```cpp
bool isAssignmentStmt() const;
```

它向后查看直到当前语句的分号；如果在合适位置发现`=`，就选择赋值语句分支。

## 八、Parser还需要一组公共工具

除了33个文法函数，还需要这些Token操作函数：

```cpp
bool isAtEnd() const;

const Token& current() const;
const Token& peek(std::size_t offset) const;

bool check(TokenType type) const;
bool checkNext(TokenType type) const;

std::unique_ptr<SyntaxNode> consume(TokenType expected);
std::unique_ptr<SyntaxNode> consumeCurrent();
```

作用分别是：

```text
current()         查看当前Token
peek(1)           查看后一个Token，但不移动
check(type)       判断当前Token类型
consume(type)     检查并读取当前Token，同时pos++
consumeCurrent()  直接读取当前Token
```

## 十、文件可以继续拆分

所有函数属于同一个`Parser`类，但不需要全部放在一个`.cpp`：

```text
parser/
├── SyntaxType.h
├── SyntaxNode.h
├── SyntaxNode.cpp
├── Parser.h
├── Parser.cpp
├── ParserExpr.cpp
├── ParserDecl.cpp
└── ParserStmt.cpp
```

建议一开始先使用一个`Parser.cpp`。当它变得很长以后，再按表达式、声明、语句拆分。

最终结构可以概括为：

```text
每个非终结符
    ↓
一个parseXXX函数
    ↓
根据Token选择文法分支
    ↓
调用更小的parse函数
    ↓
返回SyntaxNode
```

因此答案是：**几乎每一种语法类型都写一个识别函数，是这次递归下降分析最合适的结构。**少数只有一行转发逻辑，但仍建议保留，从而让代码、文法和语法树严格对应。
