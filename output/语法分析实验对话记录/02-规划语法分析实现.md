## 6. 助手

时间：2026-10-02 15:39:28

建议按 **“基础结构 → 最小程序 → 表达式 → 声明和语句 → 函数 → 错误处理”** 的顺序写，每完成一层就用小程序验证。

语法分析的核心是：**读取词法分析得到的 Token 列表，按照文法把它们组织成语法树。** 例如 `return 1 + 2;`，要识别出返回语句，以及里面的加法表达式。

你现在已有 `Lexer.tokens`、带行号的 `Token`，以及 [SyntaxType.h](/home/zzz2007-cpu/projects/compiler/src/parser/SyntaxType.h)，可以直接在这个基础上继续。

**1. 先确定文件职责**

| 文件 | 职责 |
|---|---|
| `parser/SyntaxType.h` | 定义非终结符种类，你已开始写 |
| `parser/SyntaxNode.h` | 定义语法树节点：终结符保存 Token，非终结符保存类型，节点保存有序子节点 |
| `parser/Parser.h` | 声明 Parser 的状态、辅助函数和各文法分析函数 |
| `parser/Parser.cpp` | 实现递归下降分析 |
| `parser/SyntaxNode.cpp` | 遍历语法树，输出 `parser.txt` |
| `common/Error.h` | 在已有 `a` 的基础上增加 `i`、`j`、`k` |
| `main.cpp` | 串联词法分析、语法分析和输出 |

建议让每个分析函数返回对应的语法树节点。输出单独完成，后续实验就能直接复用这棵树。

**2. 先写 Parser 的基础接口**

Parser 最基本的状态是：

- Token 列表。
- 当前读取位置 `pos`。
- 语法错误列表。

先设计几个操作：查看当前 Token、向后预读、消费一个 Token、检查预期符号，以及安全判断是否读到结尾。

这里的“消费”就是：**把当前 Token 加入节点，然后让 `pos` 前进一步。**

**3. 打通最小程序**

第一个目标只支持：

```c
int main() {
    return 0;
}
```

围绕它实现：

```text
CompUnit → MainFuncDef → Block → Stmt
                                 ↓
Exp → AddExp → MulExp → UnaryExp → PrimaryExp → Number
```

此时表达式各层先只处理单个数字。验收目标是：成功建立语法树，Token 顺序正确，输出最后出现 `<Block>`、`<MainFuncDef>`、`<CompUnit>`。

**4. 扩展表达式**

按下面的顺序增加功能：

1. 变量和数组访问：`LVal`。
2. 括号表达式、正负号和 `!`。
3. 乘除模，再加减。
4. 函数调用和实参。
5. 显式类型转换，例如 `(int)c`。
6. 比较、相等、逻辑与、逻辑或。

这里有一个重点：**`AddExp`、`MulExp` 等存在左递归，不能照着文法直接调用自己。** 应改成循环解析，并建立左结合的树。例如 `1 - 2 - 3` 应组织为 `(1 - 2) - 3`。

**5. 补齐声明、语句和函数**

| 阶段 | 要覆盖的内容 |
|---|---|
| 声明 | 常量、变量、初始化、数组、`static` |
| 普通语句 | 赋值、表达式、空语句、返回、`printf`、嵌套块 |
| 控制语句 | `if/else`、`while`、`break/continue`、`switch/case/default` |
| 函数 | 返回类型、形参、数组形参、多个函数和主函数 |

需要特别设计三个分支判断：

- 顶层的 `int x;` 和 `int f()`：通过预读区分声明与函数。
- 语句中的 `a = 1;` 和 `a + 1;`：区分赋值与表达式，考虑数组下标。
- `(a + 1)` 和 `(int)a`：区分括号表达式与类型转换。

完整课程 PDF 包含 `printf` 的专门语句规则，实施时要补上实验 Markdown 文法列表漏掉的这一项。

**6. 加入错误恢复和最终验证**

这次语法阶段处理：

| 类别码 | 含义 |
|---|---|
| `i` | 缺少 `;` |
| `j` | 缺少 `)` |
| `k` | 缺少 `]` |

缺少这些符号时，记录**前一个已消费 Token 的行号**，按“该符号已补上”的方式继续分析，保留当前 Token 给后面的规则使用。最后合并词法和语法错误，按行号输出。

输出还要注意：

- `<Decl>`、`<BType>`、`<BlockItem>` 需要分析，但不输出名称。
- 其他非终结符在其子节点输出完后输出名称。
- 加减、乘除等链式表达式，要保留文法要求的中间层节点，保证重复标签的位置正确。

**你现在先做第一步：设计 `SyntaxNode`。** 先想清楚“一个节点怎样表示 Token 或语法成分、怎样保存子节点”，再写 Parser 的基础读取接口。这样后面的每个文法函数都有明确的返回结果。
