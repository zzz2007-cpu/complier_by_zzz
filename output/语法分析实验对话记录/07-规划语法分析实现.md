**1. 先修改 `parseVarDef()`：识别数组定义**

你现在的流程是：

```text

```

```text
读取标识符
    ↓
下一个 token 是不是 LBRACK？

    └─ 否：跳过
```

```text
VarDef
├── Token: a
├── Token: [
├── ConstExp
│   └── … → Number → Token: 3
└── Token: ]
```

注意，`int` 和 `;` 由外层 `VarDecl` 处理，不属于这个 `VarDef`。

```text
    读取 ]
```

因为它们表达的含义不同：**定义数组时指定“数组有多大”，访问数组时指定“这次取哪个元素”。**

例如：

```c
const int N = 3;
int a[N + 1];    // 数组长度：编译时就能确定为 4

int i = 1;
a[i + 1] = 5;   // 数组下标：可以根据运行时 i 的值决定
```

所以课程文法规定：

| 位置 | 使用的成分 | 原因 |
|---|---|---|
| 定义 `a[长度]` | `ConstExp` | 长度要求是常量表达式 |
| 访问 `a[下标]` | `Exp` | 下标允许使用普通变量等表达式 |

**但在语法分析阶段，它们的解析过程几乎一样：**

```text
ConstExp → AddExp
Exp      → AddExp
```

两者都可以包含加减乘除、括号、标识符。`ConstExp` 并不是只能写一个数字，例如 `N + 1` 也可以是常量表达式。

区别分两阶段体现：

- **现在的语法分析：** 按出现位置调用不同函数，给语法树保留 `<ConstExp>` 或 `<Exp>` 节点。
- **后续的语义分析：** 检查常量表达式里的标识符是否为常量，并求出数组长度。

因此，你当前的 `parseConstExp()` 和 `parseExp()` 都调用 `parseAddExp()` 是合理的；外层节点不同，是为了记录它们各自的语法含义。

**`parseInitVal()` 用 `parseExp()`；`parseConstInitVal()` 用 `parseConstExp()`。** 区别取决于声明有没有 `const`，而不是有没有数组花括号。

| 初始化对象 | 单个初始化值 | `{}` 中的每个元素 |
|---|---|---|
| 普通变量或数组 | `Exp` | `Exp` |
| `const` 常量或数组 | `ConstExp` | `ConstExp` |

**数组 `{}` 里可以出现标识符，也可以出现包含标识符的表达式。**

普通数组，例如：

```c
int x = 2;
int a[3] = {x, x + 1, 4};
```

这里的 `x` 是普通变量，初始化元素按 `Exp` 解析。

常量数组，例如：

```c
const int N = 2;
const int a[3] = {N, N + 1, 4};
```

这里也能使用标识符，但要求它是常量，元素按 `ConstExp` 解析。

在当前语法分析阶段，两种情况里的标识符都会经由 `LVal` 解析；**标识符究竟是不是常量，留到语义分析时检查。**

类型转换在 **`parseUnaryExp()` 中增加一个分支**即可，对应文法：

```text
UnaryExp → '(' BType ')' UnaryExp
```

**1. 先区分类型转换和普通括号表达式**

两者都以 `(` 开头，但后面的 token 不同：

```c
(int)x      // ( 后面是类型：类型转换
(x + 1)     // ( 后面是表达式：交给 parsePrimaryExp()
```

所以判断条件是：

```text
当前是 LPARENT
并且下一个 token 是 INTTK 或 CHARTK
```

预读前检查边界。这个分支要放在兜底调用 `parsePrimaryExp()` **之前**。

**2. 按顺序添加四个子节点**

在当前的 `UnaryExp` 节点中依次加入：

```text
读取 (
调用 parseBtype()
读取 )
递归调用 parseUnaryExp()
```

例如 `(int)c` 的结构：

```text
UnaryExp
├── Token：(
├── BType
│   └── Token：int
├── Token：)
└── UnaryExp
    └── PrimaryExp
        └── LVal
            └── Token：c
```

不需要增加新的 `SyntaxType`，也不用在这里真正计算转换后的值。

**3. 最后必须调用 `parseUnaryExp()`，不是 `parseExp()`**

因为类型转换只作用于后面的一个一元表达式。例如：

```c
(int)c + 1
```

应该解析成：

```text
((int)c) + 1
```

如果调用 `parseExp()`，可能把 `c + 1` 全部吃进去，错误地解析成 `(int)(c + 1)`。

递归调用也能自然支持：

```c
(int)-c
(int)(char)x
(int)(x + 1)
```

写完先用这个程序验证：

```c

    char c = 'a';
    int x = (int)c + 1;
    return (int)(char)x;
}
```
